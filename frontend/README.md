# Netrix frontend

Предварительный фронтенд на React, TypeScript и [Vite](https://vite.dev/guide/).
Запускается независимо от сервера. Локальный mock-сервис использует 66 анкет из
переданного подготовленного JSON, включая 13 записей с `synthetic=true`.
`src/mocks/profiles.json` — побайтовая копия исходного `../profiles.json`;
исходный файл не изменяется. Копия внутри фронтенда делает сборку независимой
от наличия неотслеживаемого файла в корне репозитория. Новые анкеты не создаются.
Постоянные ограничения работы записаны в [AGENTS.md](./AGENTS.md).

## Запуск

Node.js 20.19+ или 22.12+.

```bash
cd frontend
npm ci
npm run dev
```

Откройте адрес из терминала (по умолчанию `http://localhost:5173`).
Только в режиме `npm run dev` страница `/preview` показывает все шесть
фиксированных сценариев. Переключатель подставляет соответствующий запрос в
форму и получает его ответ через mock-сервис. В собранной версии эта страница
недоступна.

```bash
npm run check
npm run preview
```

`npm run check` последовательно запускает проверку типов, все накопленные
тесты и production-сборку. Preview открывает готовую сборку на
`http://localhost:4173`.

## Структура

```text
src/
  components/                 # PageLayout, Button, Surface, форма и результаты
  pages/SearchPage.tsx        # Начальная страница поиска
  pages/PreviewPage.tsx       # Только dev: переключатель исходов
  services/contracts.ts       # Независимый предварительный контракт UI
  services/vendorService.ts   # Единая точка подключения активного сервиса
  services/mockVendorService.ts # Фабрика фиксированного сценария
  services/apiVendorService.ts  # Заглушка без сетевых запросов
  mocks/profiles.json         # Точная копия исходного подготовленного JSON
  mocks/vendors.json          # Соответствие 1:1 контрактным полям
  mocks/scenarios.ts          # Шесть пар «запрос → исход»
  styles/tokens.css           # Цвета, ширина, радиусы и тени
  styles/global.css           # Адаптивные стили и состояния компонентов
  main.tsx
```

## Контракт и подключение бэкенда

`VendorService` предоставляет `getOptions(): Promise<SearchOptions>` и
`search(request: SearchRequest): Promise<SearchResponse>`. Компоненты обращаются
только к `vendorService`, а не к HTTP или мокам напрямую.
Точка будущего подключения и предварительные пути описаны в
[BACKEND_INTEGRATION.md](./BACKEND_INTEGRATION.md).

Поля `SearchRequest`: `city`, `category`, `event_date`, `budget`, `event_format`;
необязательные — `language`, `duration_minutes`, `wishes`. Дата передаётся как
`YYYY-MM-DD`, бюджет — числом в валюте из `SearchOptions.currency` (сейчас `KZT`).
Пустые необязательные значения форма не отправляет.

Карточка содержит `id`, `name`, `city`, `category`, `price_from`, `currency`,
`price_unit`, `event_formats`, `description_detail`, `explanations`, `synthetic`,
`city_imputed`, `price_imputed`. `price_from` — цена «от», а не итоговая стоимость
события. `price_unit: null` означает неизвестную единицу цены. Пакет часов не
определяет максимальную длительность работы. Три флага сохраняют раздельный смысл:
синтетическая анкета, дополненный город, дополненная цена.

`SearchResponse` содержит:

| Поле | Смысл |
| --- | --- |
| `status` | `matches`, `no_category_in_city` или `no_matches` |
| `cards` | Карточки; пустой массив для статусов без совпадений |
| `total_matches` | Все совпадения до возможной пагинации; в демо равно длине `cards` |
| `excluded_busy` | Число занятых кандидатов; равно `exclusion_summary.busy` |
| `exclusion_summary` | Счётчики `busy`, `budget`, `event_format`, `language`, `duration` |
| `shortfall_reason` | Причина нехватки результата или `null` |

`no_category_in_city` означает отсутствие категории в городе до применения
остальных условий; `no_matches` — категория есть, но выбранный пример исключает
всех. `exclusion_summary` в демонстрации задан для конкретных анкет и дат.
`SearchResults` принимает готовый ответ сервиса и показывает не более трёх
карточек в его порядке. Счётчик занятых, причины исключения и причина нехватки
карточек выводятся из ответа без пересчёта. В карточке раскрывается блок
«Почему подходит»; оценочная цена и демонстрационный профиль отмечены отдельно.
Для начального состояния, загрузки и ошибки используются `EmptyState` и
`ResultsSkeleton` внутри той же панели результатов.
Значение `max_hours` сохранено, но без подтверждённого смысла не используется
как максимум рабочего времени. `duration_minutes`, язык и пожелания входят
в контракт запроса; текущие сценарии для них не заданы. Сценарный сервис
отклоняет запрос с этими параметрами, а не изображает подбор по ним.

CSV в репозитории отсутствует. Фактические ключи подготовленного JSON прочитаны
из `profiles.json`. `vendors.json` содержит ровно те же 66 id, без новых анкет:

| Ключ подготовленного JSON | Поле в `vendors.json` и карточке |
| --- | --- |
| `id` | `id` |
| `anon_name` | `name` |
| `categories` | `categories`; у карточки используется категория сценария |
| `city` | `city` |
| `price_from_kzt` | `price_from`, `currency: "KZT"` |
| `event_formats` | `event_formats` |
| `languages` | `languages` (для опций) |
| `busy_dates` | `busy_dates` (для проверки фиксированных примеров) |
| `description` | `description_detail` без изменения текста |
| `max_hours` | `max_hours`, не участвует в подборе |
| `synthetic`, `price_imputed`, `city_imputed` | те же три независимых флага |

Исходный JSON не сообщает единицу цены, поэтому `price_unit` равен `null`.
Отсутствие даты в `busy_dates` не доказывает доступность. Фотографии, рейтинги,
отзывы и контакты не добавляются.

`src/mocks/scenarios.ts` содержит запрос и ответ для пяти фиксированных
примеров; шестой содержит запрос и ошибку сервиса. Карточки собираются только
из явно указанных исходных id. `createMockVendorService(scenario, delayMs?)`
возвращает этот ответ лишь при точном совпадении всех полей запроса; остальные
запросы получают понятную ошибку. Полноценного поиска во фронтенде нет.
`getOptions()` берёт значения из набора анкет. Начальная форма заполнена
запросом активного сценария «три карточки». Чтобы запустить другой сценарий,
подключите его в `services/vendorService.ts`; форма получит его параметры.
Форма проверяет дату в пределах 23.09.2026–31.12.2026, положительный бюджет и
положительную целую длительность при заполнении. Ошибки показываются рядом с
полями. Сброс очищает ввод, ошибку и предыдущий результат, включая ответ,
который пришёл после сброса. Состоянием поиска и загрузкой справочников
управляет `hooks/useVendorSearch.ts` через единый сервис.

`apiVendorService.ts` пока возвращает ошибку «Бэкенд ещё не подключён» из обоих
методов и не выполняет сетевых запросов. После согласования бэкенда замените
подключение мока в `services/vendorService.ts` HTTP-адаптером. Преобразуйте
имена полей, строковые Decimal-цены, даты, статусы,
формат/категории и признаки происхождения на границе сервиса. Проверяйте
входящие JSON-данные во время выполнения, включая конечность числовых цен;
не ограничивайтесь приведением `as SearchResponse`. Не подставляйте `false`
вместо отсутствующих признаков происхождения. Точный DTO и пути API пока не
утверждены, поэтому фиктивные HTTP-маршруты не добавлены. Существующий `/chat`
возвращает `{"answer": string}` и не считается поисковым API.

## Проверка демо

Проверка: `npm run check` (типы, тест сервиса для всех сценариев и флагов,
DOM-тест формы, тест состояний результата и production-сборка). Активный
сценарий на главной странице — три карточки. Остальные доступны на `/preview`
во время разработки:

| Сценарий | Параметры | Ожидается |
| --- | --- | --- |
| Три карточки | Алматы, Декоратор, 2026-10-11, 3000000, свадьба | `matches`, три исходные карточки |
| Две и причина отсутствия третьей | Те же условия, дата 2026-10-12 | `matches`, две карточки, один занят |
| Одна | Алматы, Фото и видеобудки, 2026-10-10, 500000, свадьба | `matches`, одна карточка, один занят |
| Нет категории | Зарубежье, Флорист, 2026-10-11, 3000000, свадьба | `no_category_in_city` |
| Все исключены | Алматы, Декоратор, 2026-10-12, 1000, свадьба | `no_matches`, один занят, два выше бюджета |
| Ошибка | Запрос первого примера | `Демонстрационная ошибка сервиса` |

Мок не обращается к сети и возвращает независимые объекты при каждом вызове.
«Подобрать подрядчиков» вызывает активный сервис, «Сбросить» очищает форму и
результат, а «Почему подходит» раскрывается стандартным элементом `details`.
Отдельная кнопка «Подробнее» не нужна: исходная деталь описания уже видна в
карточке. «Связаться» отключена и подписана «Будет доступно после подключения
сервиса»; сообщение об отправке заявки не появляется.
Страница также обрабатывает загрузку и ошибки опций/поиска и показывает подпись
«Демонстрационный режим». Заявки и бронирования не отправляются. Визуальная
основа задана в `tokens.css`: фон `#F4FBF9`, зелёный `#DDF5E8`, голубой
`#E1EEFF`, белые панели с прозрачностью `0.88`, кнопка `#176B54`, основной текст
`#183B42`, второстепенный `#526B73`. `PageLayout` ограничивает содержимое
шириной `1160px`; `Surface` задаёт панели с радиусом `20px`, лёгкой тенью и
`backdrop-filter: blur(12px)` при поддержке браузером. Без поддержки blur фон
панелей остаётся белым и непрозрачным. `Button` содержит варианты `primary` и
`secondary`. Системный шрифт используется без внешнего запроса. Для проверки
откройте страницу на ширинах 390 и 1440 px и проверьте читаемость и отсутствие
горизонтальной прокрутки.
